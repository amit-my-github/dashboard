2. Why this is significantly more complex than a normal app

A normal application can store tasks and display them. This system must understand relationships between project activities and the consequences of changing dates, constraints, procurement status, approvals, RoW clearance and physical/financial progress.

3. Build vs Configure vs Integrate

Option A — Build from scratch

Maximum control, but highest cost, schedule and technical risk. Not recommended as a solo 90-day commitment.

Option B — Extend an existing platform

Potentially much faster if the base platform already supports scheduling, workflows, dashboards, RBAC and EVM. Custom renewable workflows can be added.

Option C — Configure + Integrate

Use an existing PM platform for standard capabilities and build only the POWERICA-specific gaps. This should be investigated before proposing a new platform.

Recommended approach: Do not decide the architecture or promise a complete custom build until the Discovery phase determines which capabilities can be configured, integrated or must be custom-built.

8. Questions we should ask before committing

  1. Is POWERICA expecting a replacement for Primavera P6/MS Project, or a complementary platform?
  2. Which of the 11 requirements are mandatory for Phase 1?
  3. Does POWERICA already have Primavera schedules and historical project data?
  4. How should CPM calculations behave for each dependency/constraint type?
  5. What exactly does POWERICA mean by “dynamic impact analysis”?
  6. Which EVM methodology and data sources are currently used?
  7. Which ERP/SCM/finance/document systems must be integrated?
  8. How many internal users and external contractors will use the system?
  9. Is mobile/offline field operation required?
  10. What security, hosting and data-residency requirements apply?

9. Recommended proposal position

Do not say: “We can build the complete system in 90 days.”

Say: “We propose a phased approach beginning with domain discovery and a focused MVP. Final scope, architecture, team and commercial proposal will be confirmed after validating POWERICA's project-control processes and technical requirements.”

10. Bottom line for our internal discussion

  • This is a serious enterprise project-controls platform, not a basic task-management app.
  • 90 days should be considered an MVP/proof-of-value target, not the complete platform.
  • A 12–18 month programme is a reasonable planning assumption for broad scope.
  • A multi-disciplinary team is more appropriate than a solo delivery model.
  • ₹25–35 lakh can be a possible Phase-1 range, but should not be treated as the price for the entire platform.
  • The actual Zoho commercial proposal, if available, is valuable as a benchmark.
  • Before bidding, compare each POWERICA requirement against what Zoho/Primavera already provides and identify Build vs Configure vs Integrate.
