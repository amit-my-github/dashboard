Local IIS Setup Guide for Team Access

This guide explains how to allow other team members on the office network to access the local IIS sites and APIs hosted on this development machine.

Developer machine IP: 10.99.160.175

alphahmrc API alpha.hmrc.com 80 /api C:\inetpub\hmrcstubapi

2. IIS configuration

IIS site configuration is stored in: 

C:\Windows\System32\inetsrv\config\applicationHost.config
Important: Open this file using an Administrator editor only. Do not change folder permissions or ownership unless absolutely necessary.

Current IIS site configuration

<site name="alphahmrc" id="2" serverAutoStart="true">
    <application path="/" applicationPool="alphahmrc">
        <virtualDirectory path="/" physicalPath="C:\inetpub\alphahmrcroot" />
    </application>
    <application path="/api" applicationPool="alphahmrc">
        <virtualDirectory path="/" physicalPath="C:\inetpub\hmrcstubapi" />
    </application>
    <bindings>
        <binding protocol="http" bindingInformation="*:80:alpha.hmrc.com" />
    </bindings>
</site>

<site name="dashboard" id="3">
    <application path="/" applicationPool="dashboard">
        <virtualDirectory path="/" physicalPath="C:\inetpub\localopsdashboard" />
    </application>
    <bindings>
        <binding protocol="http" bindingInformation="*:88:alpha.dashboard.com" />
    </bindings>
</site>

<site name="uktaxembeddedapp" id="4" serverAutoStart="true">
    <application path="/" applicationPool="uktaxembeddedapp">
        <virtualDirectory path="/" physicalPath="C:\inetpub\uktaxembeddedapproot" />
    </application>
    <application path="/uktaxembedded" applicationPool="uktaxembeddedapp">
        <virtualDirectory path="/" physicalPath="C:\inetpub\uktax_embedded-app" />
    </application>
    <bindings>
        <binding protocol="http" bindingInformation="*:80:dev.mtd.com" />
    </bindings>
</site>

3. Recommended approach

Because multiple sites are using port 80, the best approach is to keep hostname-based IIS bindings and ask each team member to map those hostnames to this development machine IP address.

Recommended: Keep IIS bindings as hostname-based bindings. Team members should add hosts file entries pointing to 10.99.160.175.

4. Hosts file changes for each team member

Each team member should edit their hosts file: 

C:\Windows\System32\drivers\etc\hosts

Open Notepad as Administrator:

  1. Click Start.
  2. Search for Notepad.
  3. Right-click Notepad.
  4. Select Run as administrator.
  5. Open C:\Windows\System32\drivers\etc\hosts.
  6. Change file type from Text Documents to All Files if needed.

Add the following entries

10.99.160.175    alpha.hmrc.com
10.99.160.175    alpha.dashboard.com
10.99.160.175    dev.mtd.com
Important: Remove or comment out any conflicting entries such as: 
127.0.0.1    alpha.hmrc.com
127.0.0.1    alpha.dashboard.com
127.0.0.1    dev.mtd.com

If keeping old entries for reference, comment them using #: 

#127.0.0.1    alpha.hmrc.com
#127.0.0.1    alpha.dashboard.com
#127.0.0.1    dev.mtd.com

5. Flush DNS cache

After changing the hosts file, run Command Prompt and execute: 

ipconfig /flushdns

6. Test hostname resolution

From the team member's machine, run: 

ping dev.mtd.com
ping alpha.hmrc.com
ping alpha.dashboard.com

Expected result: 

Reply from 10.99.160.175
Some office networks block ping. If ping fails, still test in browser using the URLs below.

8. Firewall configuration on developer machine

On the developer machine hosting IIS, open Command Prompt as Administrator and run: 

netsh advfirewall firewall add rule name="IIS HTTP Port 80" dir=in action=allow protocol=TCP localport=80
netsh advfirewall firewall add rule name="IIS HTTP Port 88" dir=in action=allow protocol=TCP localport=88

If using additional ports like 8080, add: 

netsh advfirewall firewall add rule name="IIS HTTP Port 8080" dir=in action=allow protocol=TCP localport=8080

9. Restart IIS

On the developer machine, run Command Prompt as Administrator: 

iisreset

10. Check IIS is listening correctly

On the developer machine, run: 

netsh http show iplisten

If the result is empty, that is usually fine. It means IIS listens on all IP addresses.

If it only shows 127.0.0.1, then add the machine IP: 

netsh http add iplisten ipaddress=10.99.160.175
iisreset

11. Verify IIS bindings using command line

On the developer machine, run: 

%windir%\system32\inetsrv\appcmd list site /text:*

To list applications: 

%windir%\system32\inetsrv\appcmd list app /text:*

To list virtual directories and physical paths: 

%windir%\system32\inetsrv\appcmd list vdir /text:*

12. Troubleshooting

Issue: Browser cannot open the site

  • Check the team member's hosts file has 10.99.160.175.
  • Run ipconfig /flushdns.
  • Check Windows Firewall allows inbound ports 80 and 88.
  • Confirm IIS is running on the developer machine.
  • Try accessing from the developer machine first.

Issue: Wrong site opens

  • Check IIS bindings in applicationHost.config.
  • Make sure each hostname is mapped correctly in hosts file.
  • Do not remove the hostnames from bindings if multiple sites share the same port.

Issue: Dashboard does not open

Remember dashboard uses port 88, so the URL must include the port: 

http://alpha.dashboard.com:88/

Issue: IP address changes

If the developer machine IP changes from 10.99.160.175, all team members must update their hosts file again.

Recommended long-term solution:

  • Ask IT for a static IP address, or
  • Ask IT for a DNS name pointing to the developer machine.
